# План: Reminder — напоминалка поверх окон (Electron)

## Цель
Личное приватное приложение для Windows на Electron + Vite + React + TypeScript. Это полупрозрачное окно, которое всегда висит поверх остальных и сворачивается в трей. В нём список ивентов, у каждого свой таймер. Когда таймер истекает, по центру основного экрана появляется уведомление. Оно висит, пока пользователь не нажмёт «Mark as done» или «Snooze». Интерфейс на английском (en-GB, формат 24 ч) и полностью в стиле Roman Design System с тремя темами.

**Профиль (roman-project-baseline):** production · настольное приложение · личное · приватное · персональных данных нет · EN · только ПК.

## Что должно работать в конце

### Ивенты
- Ивент можно создать, изменить, удалить (удержанием 1,2 с, без диалога подтверждения), переместить в архив и восстановить из него.
- Поля ивента: название, описание, категория. Категория — это название плюс цвет из `series-1…5`. По умолчанию есть Work, Health и Personal.
- Таймер задаётся составным: Months · Weeks · Days · Hours · Minutes. Заполняются только нужные поля, 1 месяц = 30 дней.
- Повтор включается переключателем. Можно указать число раз или выбрать «Until I stop». В счётчик идёт только Done. После последнего Done ивент уходит в архив.
- У каждого ивента свои часы работы (например, 07:30–16:00 или All day) и свои дни недели.
- Восстановить ивент из архива можно двумя способами:
  - «Keep previous timer»: старые параметры, счётчик повторов обнуляется;
  - «Set new timer»: открывается форма.

### Правила таймера
- Время берётся из системных часов ПК. На каждом тике сравнивается `now >= dueAt`. После выхода из сна и после смены системного времени всё пересчитывается.
- **Таймер короче 1 дня:**
  - идёт только в часы работы и в отмеченные дни;
  - в конце окна встаёт на паузу;
  - в начале следующего окна запускается с полного интервала.
  - Если интервал длиннее окна, форма не даёт сохранить ивент и объясняет почему.
- **Таймер от 1 дня:** считается календарно. Если срабатывание выпало на нерабочее время, уведомление откладывается до начала ближайшего окна.
- Следующий цикл отсчитывается от нажатия Done.
- Пока висит уведомление, остальные таймеры продолжают идти. Сработавшие одновременно ивенты встают в очередь (FIFO) и показываются по одному, следующий появляется после Done или Snooze текущего.
- Ивент в ожидании висит до подтверждения, даже когда часы работы закончились.
- Snooze: пользователь сам вводит число минут, в счётчик повторов это не идёт.
- Если изменились интервал, расписание или повтор, таймер перезапускается. Если изменились только текст или категория, таймер не трогается.

### Уведомление
- Появляется по центру основного монитора поверх всех окон. Затемнения экрана нет, это одна карточка. Его нельзя закрыть без Done или Snooze.
- Карточка непрозрачная, рамка переливается цветами (conic-gradient из токенов). При `prefers-reduced-motion` рамка сплошная accent.
- Размер подстраивается под текст: ширина от 460 px до `min(760 px, 80% ширины экрана)`, высота по содержимому, но не больше 80% экрана. Длинное описание прокручивается.
- Звук: системный или свой файл (mp3, wav, ogg).

### Пропущенные
- Если ПК был выключен или спал, при запуске открывается сводка пропущенных ивентов. Каждый ивент попадает в неё один раз.
- В сводке есть только Done на каждой строке и «Mark all as done». Done засчитывается так же, как обычный.

### Окно и трей
- Главное окно: без рамки, поверх всех окон, размер меняется перетаскиванием края, положение и размер сохраняются.
- Булавка закрепляет позицию окна.
- Ползунок прозрачности (40–100%) меняет только фон, текст и кнопки остаются чёткими.
- Режим click-through включается в настройках и выключается только из меню трея. В интерфейсе есть подсказка об этом.
- В заголовке только крестик, он прячет окно в трей. Кнопки «—» нет. Выход из приложения только через Quit в трее.
- Меню трея: Show Reminder, New event, Always on top, Click-through, Start with Windows, Quit.
- Приложение запускается в одном экземпляре. Автозапуск с Windows включается в настройках.
- Три темы: Ivory (по умолчанию), Clay и Graphite. Статусы показываются иконкой и словом. Работают клавиатура (N, E, Esc, Ctrl+S) и `prefers-reduced-motion`.

## Этапы

1. **Каркас и документы**
   - Сохранить этот план в `docs/plan.md`. Создать `docs/launch-checklist.md` по шаблону из `claude-plus-files/2026-09-25_0806-jwoq/roman-project-baseline(1)/roman-project-baseline/SKILL.md`.
   - Проект на `electron-vite` (React + TS strict).
   - Скопировать `claude-plus-files/2026-09-25_0806-jwoq/roman-design-system(1)/roman-design-system/references/tokens.css`.
   - Шрифты встроить через `@fontsource` (Manrope, Inter, JetBrains Mono). Иконки `@tabler/icons-react`. i18next с `locales/en.json`.
   - Главное окно без рамки и с прозрачностью, трей (иконка из `.../assets/roman-mark.svg`), крестик прячет окно, single instance lock, автозапуск.
   - Безопасность: `contextIsolation`, `sandbox`, без `nodeIntegration`, типизированный preload, строгий CSP, запрет навигации.

2. **Модель, хранилище, планировщик**
   - Типы Event, Category и Settings. Данные в JSON в `userData` с атомарной записью и резервной копией `.bak`, схема проверяется через zod.
   - Логика планировщика — чистые функции `(state, now) → state` в `src/shared/scheduler.ts`: тик раз в секунду в main process, очередь FIFO, done, snooze, archive, restore, `lastSeenAt`.
   - Unit-тесты на vitest:
     - пауза и перезапуск короткого таймера;
     - перенос длинного таймера на начало окна;
     - переход пятница → понедельник;
     - интервал длиннее окна;
     - составной интервал и 30-дневный месяц;
     - очередь одновременных срабатываний;
     - snooze не увеличивает счётчик;
     - последний Done отправляет в архив;
     - restore обнуляет счётчик;
     - пропущенные ивенты;
     - переход на летнее и зимнее время (Europe/Berlin);
     - ручная смена системного времени.

3. **Главное окно**
   - Экраны 1–4 из `claude-plus-files/mockups/index.html`: вкладки Active и Archive, карточки с отсчётом и прогрессом, меню «⋯», удаление удержанием, форма ивента с валидацией, настройки, категории.
   - IPC-команды; все данные, приходящие по IPC, проверяются через zod.
   - Состояния экранов: пусто, ошибка данных (баннер и Retry).

4. **Уведомление**
   - Экраны 5 и 5b из макета. Отдельное окно на основном мониторе с уровнем `alwaysOnTop: 'screen-saver'`, без возможности закрыть или свернуть.
   - Адаптивный размер: рендерер меряет себя через `ResizeObserver`, main process вызывает `setBounds` и центрирует окно.
   - Очередь «1 of N», Done, Snooze N минут, звук (системный через `shell.beep()` или свой файл, скопированный в `userData/sounds`).

5. **Пропущенные и сон**
   - `lastSeenAt` сохраняется каждые 30 с.
   - При запуске и на `powerMonitor` `resume` открывается окно сводки (экран 6 макета). Пока сводка открыта, обычные уведомления ждут.

6. **Поведение окна**
   - Прозрачность через CSS-переменную (не `setOpacity`).
   - Изменение размера и сохранение bounds. Если сохранённая позиция за пределами экранов, окно возвращается на основной.
   - Булавка через `setMovable`.
   - Click-through через `setIgnoreMouseEvents(true, { forward: true })` и пункт в трее (экран 7 макета).

7. **Доводка и сборка**
   - Проверить все три темы, контраст, клавиатуру, reduced motion и совпадение с макетом.
   - Быстрая проверка по `claude-plus-files/2026-09-25_0806-jwoq/roman-stress-test/roman-stress-test/SKILL.md` плюс smoke-тест Playwright `_electron`.
   - Быстрый аудит по `claude-plus-files/2026-09-25_0806-jwoq/roman-security-audit/roman-security-audit/SKILL.md`.
   - Сборка `.exe` через electron-builder (NSIS). Заполнить `docs/launch-checklist.md`.

- Все функции из раздела «Что должно работать в конце» работают во всех трёх темах и совпадают с `claude-plus-files/mockups/index.html`.
